# 项目视觉基准询问

## 核心流程

在开始执行视觉相关任务前，先检查用户是否已经提供以下信息：

1. 色调基准：项目应基于什么色调，以及该基准来自参考图片还是明确色彩色值。
2. 尺寸比例：输出应采用什么比例或具体尺寸。

如果任一信息缺失，先暂停实现并用简短中文提问补齐。不要把问题扩展成完整需求访谈；只问启动项目必须明确的基准。

## 必问问题

当色调基准不明确时，询问：

```text
开始前我先确认两个视觉基准：
1. 色调基准：你希望基于什么色调？参考依据是图片，还是具体色彩色值（如 #111827、#F5F1E8）？
2. 尺寸比例：目标画面/界面比例是多少？例如 1:1、4:3、16:9、9:16，或具体尺寸如 1024x1024。
```

当用户已说明部分信息时，只追问缺失项：

```text
色调基准我收到了。还需要确认尺寸比例：目标是 1:1、4:3、16:9、9:16，还是具体尺寸？
```

```text
尺寸比例我收到了。还需要确认色调基准：你希望参考图片，还是使用具体色彩色值？
```

## 接收规则

- 如果用户选择参考图片，让用户提供图片文件、截图、链接或说明要参考当前上下文中的哪张图。
- 如果用户选择色彩色值，让用户提供 1-5 个主色/辅助色；没有色值时，可以接受自然语言色调描述，但要说明会按最佳判断转成视觉基准。
- 如果用户提供具体像素尺寸，将它视为尺寸基准，不必再追问比例。
- 如果用户明确说“不需要确认”或“你来定”，直接给出保守默认值并继续执行。

## 默认值

只有在用户授权由 Codex 决定时才使用默认值：

- 色调：清爽中性底色，搭配一个明确强调色，避免单一色系铺满。
- 尺寸：未说明用途时使用 1:1；桌面网页首屏使用 16:9；移动端视觉稿使用 9:16。

继续执行前，用一句话复述最终基准，例如：

```text
收到，我会按“冷灰中性色调 + #3B82F6 强调色，16:9 比例”作为本次视觉基准继续。
```
